## Learning Mode

This project is explicitly a learning vehicle. When making changes:
- Explain the *why* behind Rails conventions being used, not just what the code does
- Call out when a pattern is "the Rails way" vs an alternative approach
- Link to relevant Rails guides or docs when introducing a new pattern (guides.rubyonrails.org, hotwired.dev)
- Prefer idiomatic Rails over clever solutions — the goal is building correct mental models

## Commands

```bash
bin/dev                        # start dev server (Rails + Tailwind watcher)
bin/rails test                 # run all tests
bin/rails test test/path/to/file_test.rb  # run a single test file
bin/rails test test/path/to/file_test.rb:42  # run a single test by line number
bin/rubocop                    # lint
bin/brakeman                   # security static analysis
bin/build                      # build image, tag with git SHA, push to ghcr.io
bin/deploy <tag>                # apply k8s manifests to the k3s cluster for the given image tag
```

## Architecture

Single-model Rails 8.1 app. One resource: `Snack` (brand, name, isaac_rating, kristina_rating, notes, tried_on, country_of_origin). The schema is the source of truth — see `db/schema.rb`.

**Frontend:** Hotwire (Turbo + Stimulus) with Tailwind CSS. No separate JS build step — importmap-rails handles JS modules. Tailwind is compiled by `tailwindcss-rails` and output to `app/assets/builds/tailwind.css`. Run `bin/dev` (not `bin/rails server`) in development so the Tailwind watcher runs alongside Rails.

**Auth:** HTTP Basic Auth in `ApplicationController#require_login`, applied to all routes via `before_action`. Credentials come from `SNACK_APP_USER` and `SNACK_APP_PASSWORD` env vars. Locally these are loaded from `.env` via `dotenv-rails`. In production, set as env vars on the k8s Deployment (see `k8s/deployment.yml`).

**Database:** SQLite in all environments. `solid_cache`, `solid_queue`, and `solid_cable` replace Redis for caching, background jobs, and websockets — all SQLite-backed. In production, the SQLite file lives on a PersistentVolumeClaim at `/data` (see `k8s/pvc.yml`).

**Deployment:** Self-hosted k3s cluster. `bin/build` builds the image and pushes it to `ghcr.io`; `bin/deploy <tag>` runs the migration Job then applies the Deployment/Service/Ingress manifests in `k8s/`. The Dockerfile is generated by `dockerfile-rails`. Health check endpoint at `/up`.
